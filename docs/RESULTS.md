## 이 작업의 존재 이유 — 정규식을 넘었는가

옛 방식은 정규식 19개로 신호를 찾아 위험도를 합성했다. 정규식이 놓친 통화를 모델이 건지지
못하면 파인튜닝을 할 이유가 없다.

```
정규식이 6~38점을 준 피싱 43건 중 41건(95%)을 모델이 70점 이상으로 판정

      id          옛 방식    새 방식
 vishing_120         6        99.9   ✓   ← 정규식이 19개 패턴 중 하나도 못 걸림
 vishing_287         6        99.8   ✓
 vishing_38         30        99.9   ✓   ← 대면편취(수거책 방문)
 vishing_680        14        16.2       ← 못 건짐. 취업 사기
 vishing_384        29         2.5       ← 못 건짐. 법원 등기 사칭
```

`vishing_120`은 `"조사 과정에서… 제3자의 인물이 없는 곳에서 통화 좀 부탁드리겠는데요"`처럼
피해자를 고립시키는 전형적 수법인데, 정규식 사전에 `"조사받"`은 있어도 `"조사 과정"`이 없어
하나도 걸리지 않았다. **정규식은 글자를 보고 모델은 뜻을 본다.**

## 실패한 2건

**`vishing_384`** (모델 2.5, 정규식 29) — `"대검찰청 이정현 사무관 / 법원 등기 우편"`.
교과서적 기관사칭인데 정규식보다도 못 봤다. 528자로 짧고 도입부가 평범한 등기 안내처럼
읽히는 것이 원인으로 보인다. **이 유형을 놓치는 것은 실제 피해로 직결된다.**

**`vishing_680`** (모델 16.2) — 취업 사기. `"아이디카드 제작 / 교육 일정 / 급여 계산"`처럼
금융 신호가 전혀 없다. 학습셋에 이 유형이 드물어 배우지 못한 것으로 보인다.

## 서버 이식 검증

맥(MPS + bf16)이 Colab(T4 + 4bit)과 같은 값을 내는지 확인했다. 수치 방식이 달라 완전 일치는
기대할 수 없으므로 **판정이 뒤집히는지**를 본다.

```
11건 대조 — 평균 차이 1.45점, 판정 뒤집힘 없음
9건은 0.2점 이내. 낮은 구간(16.2 → 1.9)에서 차이가 큰 것은 양자화 오차의 상대적 영향이다.
```

프롬프트 계약도 별도로 검증했다 — 서버가 `prompt.json`으로 재구성한 프롬프트가 학습 코드가
만든 것과 **검증셋 213건 전부 토큰 단위로 일치**했다.

## 아직 검증되지 않은 것

**① 출처 교란** — 피싱은 전부 금융감독원, 정상은 전부 AI Hub다. 두 집단은 녹음 환경과 전사
방식이 다르다. 모델이 "보이스피싱인가"가 아니라 "금감원 녹취인가"를 배웠어도 AUROC 0.9998이
나온다. 원저자들도 채널을 맞춘 평가에서 오탐률이 1% → 92~100%로 폭증했다고 보고했다.
**이 데이터로는 확인할 수 없다.** 실기기 통화가 필요하다.

> 길이 편향은 걱정보다 약하다. 길이만으로 찍은 AUROC가 0.6047이라 0.9998을 설명하지 못한다.
> (피싱 평균 1,668자 / 정상 713자로 차이가 커 보이지만, 중앙값은 602자 대 553자로 비슷하다.)

**② 확률 양극화** — 213건이 전부 `0.01` 아니면 `1.00`이다. 중간 구간이 0건이라 임계값을
0.3으로 잡든 0.9로 잡든 결과가 같고, 앱에 띄울 등급이 만들어지지 않는다.

모델 결함은 아니다 — ECE 0.006이 말하듯 확신한 게 맞았다. 검증셋이 통화 **전체**라 애매할
여지가 없었을 뿐이다. 실전은 진행 중인 통화의 앞부분만 들어오므로 다를 수 있다.

```bash
python3 evaluate.py --prefix 100    # 앞 100자만 보고 판정
python3 evaluate.py --prefix 400
```

중간값이 나오면 문제가 아니었던 것이고, 100자에서도 1.00이 나오면 모델이 내용이 아니라
말투·전사 방식을 보고 찍는다는 뜻이라 ①이 현실이라는 증거가 된다. **아직 실행하지 않았다.**

**③ 실전 입력 조건** — 학습·검증이 모두 완결된 전사본이다. 실전은 음성인식이 실시간으로
뱉는 부분 전사본이고, 오인식과 끊김이 더 많다.

## 진행 단계 판정 — 실패한 시도

확률이 0/1로만 갈리는 문제를 우회하려고, **위험도와 별개로 "사기가 어디까지 진행됐나"를
1~4단계로 매기는 것**을 원본 Gemma(어댑터 OFF)에게 시켜봤다. 설계 근거는 이랬다.

> LLM에게 확률을 물으면 학습으로 점검된 적 없는 숫자가 나오지만, **단계는 사실 관계를
> 읽는 일**이라 모델이 잘하고 사람이 채점할 수도 있다.

**이 주장은 실측에서 지지되지 않았다.** 단계 경계를 아는 텍스트를 만들어 잘라 넣었다.

```
              기대   실제
1단계까지       1     1   ✓   "서울중앙지검 김도현 검사입니다"
2단계까지       2     3   ✗   근거는 "공범으로 입건"을 맞게 인용하고 번호만 틀림
3단계까지       3     3   ✓
4단계까지       4     3   ✗   "안전계좌로 전액 이체"가 있는데도 3
```

거의 모든 입력이 3(정보·계좌)으로 떨어진다. 실제 전사본(`vishing_404`)을 400/900/1400/2200자로
잘라 넣어도 전부 3이었다.

### 왜 안 되는가

확률이 되는 이유와 대비하면 분명하다.

```
위험도   정답 후보 2개  →  한 토큰 자리의 로짓  →  학습이 3,600번 깎은 값
단계     선택지 4개    →  문장 생성            →  점검된 적 없는 자유 생성
```

단계도 결국 **생성**이다. "몇 %냐"고 묻는 것과 구조가 같아서, 피하려던 함정에 다른 이름으로
다시 들어간 셈이다. 4B가 네 정의를 동시에 저울질하지 못하고 가장 포괄적인 3번(개인정보·계좌·
앱설치)으로 쏠린다.

**다만 근거 인용은 맞다.** 읽기는 하는데 번호를 못 붙인다 — 독해 문제가 아니라 분류 문제다.

### 다음에 시도할 것 — 정규식

역설적이지만 **단계는 정규식이 통할 여지가 크다.**

```
피싱 여부   사기범이 트리거 단어를 피할 수 있다   →  정규식 실패 (위 43건이 증거)
단계        "이체해 주세요"를 피할 수 없다        →  피하면 사기가 성립하지 않는다
```

정규식이 피싱 탐지에서 실패한 이유(우회 가능)가 단계에는 적용되지 않는다. 사기범은 결국
명시적으로 요구해야 돈을 받는다. `calibrate.py`의 신호 그룹이 그대로 단계에 대응한다 —
`IMPERSONATION`→1, `PRETEXT`→2, `DEMAND`(정보·계좌)→3, `DEMAND`(이체·수거)→4.

결정론적이고, 빠르고(7초 → 0초), 사람이 전사본을 보고 채점할 수 있다.

## 참고 — 지어낸 문장으로 해본 것

학습셋 밖 텍스트에 대한 반응을 보려고 통화 4건을 **작성해서** 넣었다. 데이터셋이 아니다.

```
기관사칭(피싱)      99.9  ✓        은행 정기예금 상담(정상)   2.8  ✓
대출빙자(피싱)      99.6  ✓        카드 재발급 안내(정상)     1.6  ✓
```

학습셋의 정상 표본에 금융 통화가 **0건**이라 "금융 어휘=피싱"으로 배웠을 위험이 있었는데,
은행·카드사 통화를 정상으로 판정했다. 키워드가 아니라 구조를 본다는 정황이다.

**다만 이것을 성능 근거로 쓰면 안 된다.** 모델이 무엇으로 학습했는지 아는 쪽이 문장을 지었고,
실제 전사본의 말더듬·중복이 없는 깔끔한 문장이며, 학습 분포 밖 입력에 99.9/1.6이라는 극단값을
내는 것 자체가 ②의 재확인이다.
